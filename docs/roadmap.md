# Roadmap

Frame's goal is to be the open-source application security platform: code (SAST), dependencies (SCA), secrets, infrastructure and containers, AI application security and autonomous pentesting, all on one engine, where every finding says how strongly it is proven. An LLM, frontier or local, stays an optional add-on at every stage.

The phases are ordered so that each one builds on the last. Pick work from the earliest phase that is not done.

## Principles

- **One engine, reused everywhere.** The program model (SIL, the project index, canonical call ids, taint, Z3) serves every domain: SCA reachability is "is this vulnerable function called", LLM app security is taint with new source and sink kinds, pentest recon reads routes from the packs' entrypoints.
- **Knowledge is data.** What Frame knows about languages, frameworks, rules, advisories and secret formats lives in versioned, data-only files (TOML/JSON, never code), not in the engine.
- **Every finding carries its evidence.** One finding model across all domains, with an evidence level: matched, reachable, path proven feasible by the solver, LLM-triaged, exploit-confirmed. Fingerprints, baselines, `verify`, SARIF, the GitHub Action, the pre-commit hook and MCP work the same for every category.
- **No benchmark-specific behaviour.** Every change is checked against the full benchmark sweep (identical results unless the change intends otherwise), and solver changes against every SL-COMP division.

## Phase 0: close the SAST known gaps (done, October 2026)

All 37 gaps that were strict xfails in `tests/e2e/test_known_gaps_*.py` are now regular vulnerable/safe cases; a newly found gap goes there first.

Done (October 2026): extensionless shebang scripts, a warning for files that do not parse, C constant shifts (`1u << 20`), a Java redirect target reassigned to a constant on the bad branch, JS path containment (`path.resolve` + `startsWith(BASE)`), JS prototype methods.

**A. Taint stored in object state**: done. A constructor or setter storing attacker data in a field reaches a sink in another method of the object (Java, C#, Python, JS); a Python `@property` returning request data; Express middleware setting `req.x` for the handlers of the same app; a servlet Filter's request attribute read by a servlet.

**B. Call resolution**: done. Interfaces with several implementations (taint reaches each, Java and C#), C# extension methods and partial classes, Java static-factory chains, instances a module exports or builds at its top level (Python `repo = Repo()`, JS `module.exports = new Mailer()`, an object-literal DI container), CommonJS barrels (`module.exports = { ...require("./q") }`), `functools.partial`, and Django managers held as class attributes.

**C. C/C++ validation idioms**: done. `strcmp` allowlists, `strspn` charset checks, a loop rejecting the first character that fails `isalnum` (or another character-class test), `strncmp` against a fixed `scheme://host/` prefix, a lookup in a table of literals (`std::map::find`), numeric conversion inside `snprintf` (`atoi`), and a `memcpy` length checked on the path (the length, not the copied bytes, is the sink).

**D. C/C++ interprocedural and memory**: done. Attacker data passed into a helper function reaches its sinks (the interprocedural fixpoint runs for C/C++, including C++ overload sets); `sprintf` of attacker text that can exceed the destination; an attacker index into a file-scope array; a branch that frees and returns no longer makes the later free a double free; `new[]` stored in a member (also from a constructor's initializer list, now lowered) released with `delete`. The line-based `system()`/`popen()` rule, which flagged every call whether tainted or not, is gone.

**E. Weak randomness by flow**: done. `rand()`/`random()`/`drand48()` output is `weak_random` taint, reported as CWE-338 only where a value must be unpredictable (a `Set-Cookie` header, an `EVP_*Init` key or IV, an HMAC key, a PBKDF2 salt, a CSPRNG seed), also through a helper that fills a buffer; it never counts as an injection payload. Python, JS and Java still report every non-cryptographic random call (OWASP Benchmark scores weak randomness that way); moving them to the flow rule is a separate, measured change.

**Engine fixes found along the way**: an assignment that is not a literal forgets the variable's constant (`nonconst`), so code after `for (i = 0; i < N; i++)` is analysed (it was unreachable, hidden by the removed `system()` line rule); a C store taints the buffer it writes into; `n = strlen(buf)` is bounded by buf's capacity.

**Engine debts found along the way**: done. Sanitization checks resolve sink-kind aliases (`path` is `filesystem`); assigning a plain local is a strong update (its old taint goes unless the new value reads it); Python `os.path.realpath`/`normpath` are no longer sanitizers on their own (a `startswith(BASE)` check on the normalised path is); Java numeric parsing (`Integer.parseInt`, ...) sanitizes text-payload sinks; a ternary takes the branch its condition folds to over known constants, replacing a heuristic keyed on the words "always"/"never".

## Phase 1: foundations

- Done: **workspace inventory** (`frame inventory`, `frame/sil/inventory.py`): languages, frameworks (packs whose `detect` matched), manifests and lockfiles by ecosystem, IaC (Terraform, Kubernetes, Helm, CloudFormation, Compose), Dockerfiles, LLM SDKs and MCP servers.
- Done: **unified finding model** (`frame/sil/findings.py`): every finding has a `category` (taint, memory, crypto, secret, access-control, hardening; dependency, iac, container and ai reserved) and an `evidence` level (matched, llm-detected, llm-verified, data-flow, solver-verified, exploit-confirmed), in JSON and SARIF.
- **Knowledge base (KB)**:
  - Done: the client (`frame/kb`, `frame kb pull | status | build`). A revision is a directory with `manifest.json` (every file's SHA-256, size, language, kind) and data files; `pull` downloads only the project's languages, verifies each file, caches it, and can pin the revision in `.frame/kb.lock`; scans load cached packs (they replace built-in packs of the same name) and never fetch. Sources: `hf:org/dataset`, an HTTPS mirror, or a local directory for air-gapped CI.
  - Done: the `lambdasec/frame-kb` dataset, published from a private source repo on every merge (check, build, upload, tag); the first published revisions carry the 77 packs and the six spec tables. Manifest signing is deferred.
  - Done: the language specs are data (`frame/sil/specs/data/<table>.toml`, 2,888 entries across six tables), identical in order and fields to the Python tables they replace; the KB can ship them too (`frame kb build --specs`).
- **Config cleanup**: `.frame.toml` holds project settings only (severities, excludes, extra packs; the KB pin is `.frame/kb.lock`). Packs describe code; rules become pack kinds. Done: `[[setting]]` (configuration that switches a protection off) replaces the hard-coded hardening rules, with `files`/`module_names` detect keys for settings modules. Secret formats and advisories arrive as kinds with Phases 2 and 3. Only what cannot be data (C memory analysis, the solver) stays in the engine.
- **Licensing**: packs Apache-2.0, datasets CC-BY-4.0.

## Phase 2: SCA

- Done: the dependency graph (`frame deps`, `frame/sca/`) from lockfiles and manifests: Python (`requirements*.txt` with `-r` includes, `pyproject.toml`, `poetry.lock`, `uv.lock`, `pdm.lock`, `Pipfile.lock`), JS (`package.json`, `package-lock.json` v1-v3, `yarn.lock` classic and berry, `pnpm-lock.yaml` v5-v9), Java (`pom.xml` with properties and dependency management, `gradle.lockfile`), C# (`packages.lock.json`, `*.csproj`, `packages.config`), and, for dependencies only, Go (`go.mod`), Rust (`Cargo.lock` with `Cargo.toml` for dev) and Swift (`Package.resolved`). Exact versions, edges, direct (from the manifest beside a lockfile, else unknown), dev only (the lockfile's flag, else unreachable from a production dependency), package URLs. Not read without the build tool: Maven and Gradle transitive resolution.
- Done: resolved graphs for Java and .NET (Maven `dependency:tree` text and JSON, Gradle `dependencies` reports, `obj/project.assets.json`, `Directory.Packages.props`), and `frame deps --resolve`, which runs Maven, Gradle and pip (dry run, wheels only) for projects without a lockfile.
- Done: Ruby, PHP, Dart and Elixir (`frame/sca/morelocks.py`): Gemfile.lock (+ Gemfile groups; the gemspec's and git gems' dependencies are production), composer.lock, pubspec.lock, mix.lock (an Elixir term reader; optional dependencies are not edges), with RubyGems / Composer / pub / Hex version order and requirements; matching agrees with the OSV API on every package of four real projects. They are checked in `sca-real` against bundler, composer, dart and mix.
- Done: Gradle build scripts without running Gradle (`frame/sca/gradle.py`): `build.gradle` / `build.gradle.kts` declarations (string, map and named-argument notation, `$var` from the script, `ext` and `gradle.properties`, `platform(...)`) and the version catalog (`gradle/libs.versions.toml`, refs and bundles); test, kapt/ksp and annotation-processor configurations and `buildscript` are dev only. A lockfile or report beside them wins. The declared names equal Gradle's own direct dependencies on the real-tool fixtures. `--apply` edits a literal coordinate or the catalog, only when re-reading the catalog shows that library alone moved (a shared `version.ref` stays manual).
- Done: C/C++ dependencies (`frame/sca/cppdeps.py`, `cpp.py`, `cmake.py`): Conan, vcpkg, submodules, CMake fetches, each resolved to its upstream repository and tag (a map generated from vcpkg ports and Conan Center recipes, `frame/sca/data/cpp-repos.json`) and matched against OSV's GIT advisories by affected tag, sharded by repository (the Linux kernel's git.kernel.org records are left to the OS work). Done: commit-range matching for a submodule pinned to an untagged commit (`frame/sca/gitrange.py`: OSV's GIT `introduced`/`fixed`/`last_affected`/`limit` commits decided by ancestry in the submodule's own checkout; equal to OSV's commit query on every commit its index answers for, on zlib and libexpat). Done: vendored copies (`frame/sca/vendored.py`, `data/vendored.json`): fourteen common libraries known by the version their own header declares, next to their own sources, matched by release tag; every entry checked against real releases and OSV's listed tags. Done: copies whose version header was dropped, known by their source files' git blob ids at each release tag (`data/vendored-fingerprints.json.gz`, 28 libraries, 2,003 releases, each file at its path upstream so a copy spanning folders is one copy); a file shared by several releases decides only the advisories all of them agree on, the rest are not decided. Done: fifteen more (wolfSSL, mongoose, LibRaw, YARA, libssh2, libgit2, zstd, lz4, civetweb, tinyxml2, jansson, protobuf-c, libuv, llhttp, libtiff: 29 in all), each checked against a real release and its tag forms against OSV's. Next: more libraries as OSV's GIT records grow (each needs a header that states the version, or sources in its repository; openjpeg, libjpeg-turbo, libheif, exiv2 and libevent generate theirs at build time).
- Go reachability comes from `govulncheck -json` when a report is present (it uses the compiler's call graph); Frame imports it rather than re-deriving it.
- Done: advisory matching (`frame/sca/versions.py`, `osv.py`, `advisories.py`; `frame deps --vulns`, `frame kb pull --advisories`, `frame kb build-advisories`). Version order per registry, checked against Maven's own ComparableVersion, `packaging` and npm's semver; OSV range semantics checked against the OSV API's answers for 29 vulnerable and fixed versions across all seven ecosystems; aliases merged; CVSS v3 base scores.
- Advisories: a separate dataset, `lambdasec/frame-advisories`, published by the same machinery as `frame-kb` but rebuilt daily from OSV (packs change with Frame and are pinned per project; advisories should be current by default, with an optional pin for reproducible audits). Compact per-ecosystem files (`advisories/<ecosystem>.json`: package, affected ranges, fixed versions, ids, severity), so `pull` fetches only what a project uses; each source keeps its licence.
- Vulnerable functions per advisory, in the same dataset (`functions/<ecosystem>.json`, CC-BY-4.0, keyed by advisory id, rebuilt on its own schedule and joined at load time): Frame canonical call ids with provenance, `osv` (Go's `ecosystem_specific.imports[].symbols`), `fix-commit` (the public functions a fix commit changed, found with Frame's frontends) or `curated`. Reachability evidence carries the provenance.
- Done: reachability levels installed, imported, called (`frame/sca/reachability.py`): imports and calls from Frame's frontends (`Program.imports`, `Call.canonical`; C# `using` plus `Type.Method` only when it equals the advisory's own id), PyPI module names from the project's virtualenv, else a table. Positive evidence only. Vulnerable-function data ships as `functions/<Ecosystem>.json.gz` in the advisory dataset (`frame kb build-advisories --functions`), merged by advisory id or alias.
- Done: the tainted level (`frame scan --sca`, `frame/sca/scan.py`): vulnerable functions become sinks of a generated pack (`only_if_not_sink`), and a finding counts for an advisory only when its sink call (`Vulnerability.sink_call`) is that function at that call site. Curated function files ship in the dataset (daily).
- Done: fix-commit mining (`frame kb mine-functions`, `frame/sca/mine.py`): the public functions an advisory's GitHub fix commit changed, as canonical ids (Java/C# package.Class.method; Python from the package's import name in the repository path; JS only for exported functions), internal changes lifted to the public functions of the same file that call them; a fix outside any function (PyYAML's) is listed for curation. Done: it runs weekly in the dataset's source repo, resuming where the last run stopped. Same-file lifting follows chains of any length (each function once): on the miner's real needs-curation list, 2 of the 10 internal-only advisories now lift (AntiSamy's fix reaches the public scan through four private callers). Of the 68 needing curation, 58 change code outside any function (field initialisers, class-level code), which needs a person. Done: when no function can be named, a Java / C# fix still records the classes it changed (`"kind": "class"`, from the file's own package declaration), which give the `imported` level through their package (Maven coordinates do not name a Java package): on that list, 56 of 68 gain classes; the 8 without are npm, which already falls back to the package. Lifting across the files of a Java package (through the frontend's resolved receiver classes, never by name) was built and measured on the same list: it found nothing more. The remaining internal-only fixes are server internals (Tomcat's HTTP/2 settings are called only from the package-private `Http2UpgradeHandler`, driven through an interface; netty's QPACK decoder likewise), a serialization hook the JVM calls, or test code: there is no public method an application calls, so they stay with curation, and the code was not kept.
- Done (npm, PyPI, crates.io, NuGet; Go needs none): Z3 remediation planning (`frame deps --plan --registry`, `frame/sca/solve.py`, `registry.py`): the vulnerable packages and their ancestors, every candidate version's ranges from the registry, hard range constraints, soft "no vulnerable version", minimising major jumps, raised requirements, packages changed and distance; a package a newer parent no longer needs leaves the tree. On a real Express app it replaces 11 overrides with upgrades, and real npm re-locking leaves 0 vulnerabilities (live test). PyPI reads each version's `requires_dist`; uv.lock (no ranges between packages) gets them from PyPI, an unknown range holds the child (never `*`), and the plan lists the other packages re-locking must move. Done: declared ranges that admit a vulnerable release, with the floor that excludes them (`--vulns --registry`), since a library's users resolve its ranges, not its lockfile. crates.io reads the sparse index (dev-dependencies are not edges, optional ones are kept), and Cargo re-locks package by package, retried in dependency order. Done: NuGet (nuget.org's registration index), modelling its lowest-applicable resolution (a transitive package is the lowest version all its parents admit, so re-locking never moves one): on a real Azure.Identity project one raised reference replaces the MSAL override, and real `dotnet restore` leaves 0 vulnerabilities. Go uses Minimal Version Selection over a `go.mod` that lists every module, so a raised line always takes effect; `--registry` reads each target's `go.mod` from the module proxy and names a fix that needs a newer Go than the module's `go` directive, plus the newest fix that Go builds (checked with real `go mod tidy`). An advisory with no fixed version no longer blocks a package's other fixes. Maven resolves nearest-wins rather than by ranges, so its fix stays `dependencyManagement`.
- Done: SBOM (`frame deps --sbom cyclonedx|spdx`, `frame/sca/sbom.py`): CycloneDX 1.6 and SPDX 2.3 from the graph, validated against the official schemas on all 25 real package-manager fixtures; licences only where there is evidence.
- Done: licence policy (`frame deps --licenses`, `frame/sca/licenses.py`): licences from the lockfile (npm, Composer) or the installed metadata of the same version (`node_modules` incl. pnpm's store, a project virtualenv's `License-Expression` / SPDX `License`); a `[licenses]` table (`deny`, `allow`, globs, `unknown = "report"|"fail"`, `include_dev`) evaluated over the SPDX expression (OR: either, AND: both, WITH: the exception named exactly or not at all); exit 1 on a violation. Matches pnpm's own `pnpm licenses list` live. Done: licences from each version's own registry record (`--licenses --registry`, `frame/sca/licreg.py`: npm, PyPI, RubyGems, crates.io, NuGet), checked live against each `.gem`, `cargo metadata` and each nuspec; Hex (latest release only), pub.dev and Go publish none per version. Done: Maven POM licences (inherited through parent POMs as Maven does, checked against `mvn help:effective-pom`; mapped to an SPDX id only when SPDX's own list makes the URL or name unique).
- Remediation (`frame fix` for dependencies), deterministic first, the LLM only where judgement is needed, every fix verified by Frame:
  1. Upgrade. Done: the plan (`frame deps --vulns --plan`, `frame/sca/plan.py`, `ranges.py`): the minimum version clear of every advisory, and re-lock / raise-requirement / override from the declared ranges (npm ranges checked against node-semver, PEP 440 against `packaging`). Done: applying it (`--apply`, `frame/sca/apply.py`: minimal manifest edits per ecosystem, `--relock` through the package manager, then the graph re-read and re-matched; a live test re-locks through real npm in CI). Done: `--verify COMMAND` runs the project's build or tests before and after and rolls back an upgrade that breaks a passing command. Done for npm, PyPI, crates.io and NuGet: upgrading the packages in between, solved with Z3 (`--registry`, below); Go needs no solver.
  2. Done: breaking-change adaptation (`--adapt`, `frame/sca/adapt.py`): when an upgrade breaks the project's `--verify` command, a model gets the failing output and the files that import the upgraded packages and proposes minimal source edits (never manifests or lockfiles), for up to three rounds; kept only if the command passes and a re-scan of the edited files finds nothing new (a re-scan that cannot run restores them), else everything is rolled back. Live: DeepSeek adapts a Werkzeug 2 -> 3 upgrade (removed `url_parse` / `url_quote`) in one round. Done: the model also gets the release notes between the two versions (`frame/sca/notes.py`: the changelog file at the target's tag sliced to those versions' sections, feature releases first, else GitHub release bodies).
  3. Done: code mitigation (`frame fix DIR --deps`, `frame/sca/mitigate.py`): the LLM proposes, the taint engine decides by re-running the whole analysis on a patched copy (removed / untainted, nothing new); exact-value guards (constant allowlists, equality) cut a flow to a vulnerable function, character classes do not.
  4. Done: configuration mitigation (`frame/sca/mitigations.py`): curated per advisory from the advisory's text and the library's source (`data/mitigations/`, plus `mitigations/<Ecosystem>.json.gz` in the dataset), with the versions where the setting exists and whether it is complete or partial (Log4Shell's `formatMsgNoLookups` is partial: it does not stop CVE-2021-45046). Found where a running application gets it (Dockerfile, Compose, Kubernetes, systemd, shell, `.env`, properties files, Java source), never in build configuration; evidence in `frame deps --vulns` and VEX notes, never a `not_affected` Frame states itself. Done: `--mitigate` writes a complete one (a classpath properties file, else the Dockerfile's last stage, keeping earlier JVM options) and confirms it by re-reading the project; partial ones are never written. Next: more curated entries.
  5. Backported patches (upstream fix commit applied to the pinned version, `patch-package`, vendoring) when no upgrade is possible.
  6. Done: VEX (`frame deps --vex`, `frame scan --sca --vex`, `frame/sca/vex.py`): OpenVEX 0.2.0 and CycloneDX 1.6, validated in tests against the official schemas; `affected` with the plan's upgrade, `exploitable` for a verified flow, `not_affected` only from a decision recorded in `.frame/vex.toml` (and never against a verified flow) or opt-in for dev-only dependencies.

## Source languages

SAST covers Python, JavaScript/TypeScript, Java, C# and C/C++: the most used languages, each with a public benchmark, and C/C++ where the separation logic engine decides memory safety. Dependencies are read for more ecosystems than that (Go, Rust, Swift), because an inventory or SBOM that omits part of a repository is wrong. Next SAST languages, on demand: PHP (a large share of web CVEs, injection-heavy), then Go (strong existing tools: `govulncheck`, `gosec`), then Swift and Kotlin with mobile-specific checks. Rust: only `unsafe` code can hold the memory errors the engine proves, a research item.

## Phase 3: secrets, infrastructure, containers

- Secrets. Done: provider key formats as data (`specs/data/secret-formats.toml`, 17 formats with the provider's documentation and published example values), reported in any string literal of any language, read from the syntax tree (not comments), alongside the name-based rule and its value-shape gate. Done: git history (`frame history`, `frame/sil/secret_history.py`): every added line of every ref, each credential once at its first commit, whether HEAD still has it, values never printed; every credential gitleaks finds is found at the same commit, file and line. Done: test code recognised from the program model, not file names (`frame/sil/test_code.py`: a test framework's import, test attributes and annotations, asserting pytest functions, jest/mocha callbacks; findings tagged `context: "test"`, a name-based credential lowered to low, a provider-format one kept). Done: live verification, opt-in (`--verify-secrets`, `frame history --verify`, `frame/sil/secret_verify.py`): a read-only request to the provider's own API for 10 formats (GitHub, Slack, Stripe, OpenAI, Anthropic, SendGrid, Hugging Face, DigitalOcean, npm), valid / invalid / unverified; every endpoint confirmed live with a fake token (rejected) and GitHub's with a real one (accepted).
- IaC: Terraform, Kubernetes, Helm, CloudFormation, Dockerfiles (tree-sitter grammars); policies as KB packs; Z3 for reachability-style policy questions ("can the internet reach this bucket").
- Done: containers (`frame deps --image` / `--rootfs`, `frame/sca/container.py`, `distro_versions.py`). Debian, Ubuntu and Alpine OS packages, from an image's layers (whiteouts honoured) or a root filesystem, keyed by source package and release. dpkg and apk version order are checked against the real tools (0 disagreements on 2,186 pairs; apk's is a port of apk-tools 2.14.4). On the official debian:12.0 and alpine:3.18.0 images, the packages equal `dpkg-query` / `apk list` and the advisories equal OSV's API (202, 22). Done: the distribution advisories are in the daily dataset build (50 releases; one table per release, pulled alone). Tables are compacted losslessly (a listed version a range covers is dropped, a shared summary stored once), which took Ubuntu 22.04 from 108 MB to 15.9 MB and the build's peak memory from 11.8 GB to 7.5 GB. Done: language packages inside an image (PyPI dist-info, npm package.json, jars' pom.properties including nested jars), equal to `importlib.metadata`, `npm ls` and the jars' coordinates on a real image; packages an OS package owns (dpkg file lists, apk `F:` lines) are left to the distribution's advisories. Done: Go binaries (build info, Go 1.18+, replacements applied, the standard library as `stdlib`) and Rust binaries built with `cargo auditable` (`frame/sca/binaries.py`), equal to `go version -m` and `rust-audit-info` on real binaries. Done: the vulnerable functions a Go binary contains (its `pclntab`, which stripping keeps; advisories' `goos`/`goarch` respected) mark an advisory `called`, equal to `govulncheck -mode binary` on the unstripped build (54 of 89 stdlib advisories on a small server; govulncheck on the stripped binary reports 85). Done: AlmaLinux and Rocky Linux (`frame/sca/rpmdb.py`: sqlite and Berkeley DB rpm databases, equal to `rpm -qa` on the official 8 and 9 images; rpm version order ported from `rpmvercmp`, 0 disagreements with `labelCompare` on 6,861 pairs; Rocky keyed by source package, AlmaLinux by binary, as their advisories name them; matching equal to OSV's API). Done: Wolfi and Chainguard's images (`ID=wolfi`): apk, matched by each package's own name (Wolfi's advisories name subpackages, unlike Alpine's), the CGA records' `upstream` CVE read as an alias; equal to OSV's API on `wolfi-base` and `python:latest-dev`. ## Phase 4: AI application security

- Done: LLM taint. Untrusted data in a model's system instructions is prompt injection (CWE-1427, a `prompt` sink kind; a user turn is not), and model output is an `llm` source kind, attacker data at every injection sink but not at confidentiality sinks (logs). Findings are in the `ai` category. Done: role/content chat messages (`{"role": "system", "content": x}`, the OpenAI chat format) in Python and JS/TS: the frontends lower a message whose role is the literal `system` or `developer` as a system-message construction, which the LLM packs make a prompt sink, wherever the messages list is built. Done: retrieved documents and tool output as sources (indirect injection; `retrieved`, the `llm-context` packs): LangChain vector-store searches and retrievers, MCP client tool results, resources and prompts, Python and JS; method names checked against `langchain_core`, `@langchain/core` and both MCP SDKs. Pack constructor ids are also registered as `new X` (JS `new SystemMessage(...)` was never a sink).
- Done: packs for the OpenAI, Anthropic, LangChain and LlamaIndex SDKs (`llm-sdks`, Python and JS/TS), matched on SDK clients through their constructors (JS now binds `const client = new OpenAI()` like Python).
- Done: MCP servers. Tool handlers (`@mcp.tool()`, `server.tool` / `server.registerTool`) are entry points whose arguments are model output, including destructured parameters (`async ({ path }) => ...`). Done: tool metadata (`frame/sil/mcp_metadata.py`): hidden characters in names, descriptions and parameter descriptions (tag characters decoded, bidi controls, zero-width), descriptions computed at run time, Python (FastMCP, low-level `Tool`) and JS/TS (`tool`, `registerTool`, `addTool`); each tool's capabilities in `frame inventory`. The wording of a description is not judged (no phrase lists); `--ai` is where that belongs.
- Not planned: detecting AI-generated code. Detectors are unreliable and authorship does not change whether code is vulnerable; guardrails on agent edits (pre-commit, `--files`, MCP) cover the need.

## Phase 5: autonomous pentesting

- Grey-box: inventory, routes from entrypoint packs, SAST findings and reachable SCA vulnerabilities become the attack plan for `frame exploit`, with a frontier or local model.
- Add for black-box work: crawling and OpenAPI import, authentication and sessions (needed for IDOR), parallel hypotheses, an independent validator for every claimed exploit, scope and safety controls.
- Measure on XBOW's validation benchmark and CVE-Bench, blind and primed with Frame's findings.
- Later: attacks on LLM apps and agents (prompt injection payloads, tool abuse).
